# 市场调研与竞品基线

> 最近复核：2026-08-04
>
> 本文档只记录竞品事实、证据边界和产品结论，不跟踪工程进度。产品优先级与状态以
> [00-roadmap.md](./00-roadmap.md) 为准。

## 1. 调研结论

Supplier 要进入的不是单点 AI 工具市场，而是已经成熟的 **1688 分销经营工具**市场。用户对基础能力的预期不是“帮我生成标题”，而是能把以下链路连续跑完：

> **找货 → 选品 → 铺货 → 商品管理 → 订单回流 → 1688 采购 → 物流发货 → 售后 → 利润复盘**

因此，Supplier 的产品主体应是完整经营链路；AI 用于提升选品、内容、定价、类目映射和风险判断。只有 AI 而缺少批量经营、履约和售后，无法替代现有工具。

## 2. 证据说明

| 证据等级 | 含义                                                       |
| -------- | ---------------------------------------------------------- |
| A        | 已用真实付费或试用账号验证产品行为、限制和价格             |
| B        | 竞品官方公开页面的明确宣称，尚未验证真实产品行为           |
| C        | 历史截图、搜索摘要或无法实时访问的页面，只能作为待核验线索 |

本轮没有 A 级证据，只把 B 级信息写成“竞品官方公开宣称”。价格、销量、稳定性和真实操作体验仍需购买或试用账号验证。

## 3. 核心对标产品

### 3.1 1688 分销 AI 工作台

[官方首页](https://fenxiao.1688.com/) 与四张公开功能图本轮仍可核对，可确认 AI 选品、组货、跟单、下游店铺、商品管理和自动化工作流等公开定位；进入网页版动态工作台后仍要求登录，因此没有验证账号内行为、完整平台支持矩阵、套餐与稳定性。

**官方工作台公开能力：**

- 主题、榜单和自定义条件选品，可按价格、成交、代销和商家等条件筛选并直接铺货
- 在售、已下架和草稿商品管理，以及批量下架、改价、改库存、改 SKU、改运费模板和销售渠道
- 面向已绑定店铺配置选品与铺货工作流，展示执行进度和预计完成时间；复杂自动化标为客户端专属
- AI 经营助手覆盖目标利润定价、下游出单后采购、买家退款和供应商不发货后的换源等场景

**官网合作服务商公开能力：**

- 多平台铺货、下游订单同步、自动或批量采购、按供应商拆单
- 库存与商品信息同步、物流回传、自动发货、售后/退款、退货地址同步
- 多店管理和利润分析

上述合作服务商能力不等同于 1688 官方工作台原生实现；官网也没有公开套餐、全平台总价、API scope、SLA、失败补偿和安全边界。AI 客服、AI 员工、AI 比价、AI 数据分析、AI 写作和 AI 作图在页面中明确标为“开发中”，不能计入当前可用能力。

**可超越点：**

- 明确区分 Supplier 原生能力、平台能力和第三方能力，避免用户不知道谁对结果负责
- 用纯 SaaS 优先的统一工作台减少客户端依赖，并把失败、恢复、审计和人工接管做成一等能力
- 公开店铺数、SKU、订单量、AI 配额和全部费用，避免“单项免费”被误解为整套免费

证据等级：**B，官方首页与功能图已核对；真实账号行为、价格和稳定性待试用验证**。

### 3.2 逸淘

官网按多款、分平台的软件/插件呈现；这些产品是否共享统一后台，需要真实试用确认。

**铺货与商品管理**（来源：[铺货产品页](https://www.1tsoft.com/html/inventory.html)）：

- 一键多店铺货、商品管理和 1688 商品采集
- 商品同步、密文商品检测和库存/价格自动同步；页面功能图出现“图片编辑”标签
- 页面问题说明提到“同步 SKU”，但是否等同于稳定的同款换源仍需账号内验证
- 无流量/无销量商品清理、爆款裂变等批量经营功能

**分销与履约**（主要来源：[官网能力总览](https://www.1tsoft.com/index.html)、[分销产品页](https://www.1tsoft.com/html/distribution.html)和[采购/下单入口页](https://www.1tsoft.com/html/pay_down.html)）：

- 多店订单和利润查询
- 组合套装关联、自动下单和免密支付
- 实时自动发货、自动统计利润和 1688 自动售后；订单如何关联上家及密文下单深度仍需账号内验证

**平台覆盖**（来源：[官网](https://www.1tsoft.com/index.html)、[软件下载与使用页](https://www.1tsoft.com/html/pay_down.html)）：

- 官网展示淘宝、抖音、拼多多、快手、小红书、视频号等不同软件或插件
- 移动端公开展示多店、订单、利润、采购、支付、发货和售后；订单/退款提醒的具体触达渠道仍待账号内验证

**公开价格：**

- 抖店服务市场“逸淘一键下单”公开订购页列出 7 天试用版 0 元，以及普通版 18 元 / 月、54 元 / 3 个月、108 元 / 6 个月、216 元 / 年；页面标注仅支持 PC 端
- 该抖店页面的试用版与普通版功能表均勾选一键下单、自动发货、售后处理、利润统计和多店铺管理，但未公开店铺数、订单量和铺货量限制
- 抖店“张飞搬家 / 逸淘商品管理”公开订购页按每月上新量分档：本轮复核到 1000 商品标准版 128 元 / 年、3000 商品高定版 200 元 / 年；此前公开页面还记录 9000 商品旗舰版 888 元 / 年，但本轮未重新确认该档。商品工具与订单工具是独立产品，完整组合成本不能只看其中一个最低价
- 淘宝“逸掌柜交易”另有标准版 20 元 / 月、高级版 50 元 / 月、定制版 68 元 / 月的公开价格，进一步说明不同平台和功能模块独立售卖
- 1688「逸淘分销铺货」当前页面可见免费版、高级版和“免费版 3 个月 0 元”，购买仍要求登录；此前公开套餐接口曾记录高级版 50 元 / 月、135 元 / 3 个月、240 元 / 半年、420 元 / 年，但本轮未在渲染页复现完整数字。页面服务商与逸淘官网主体也不一致，因此只把这些数字作为待复核的 B 级公开报价，不当成真实成交价
- 独立跨境 ERP 另有 0 元 / 月免费版和 150 元 / 月或 1680 元 / 年 VIP，但功能与国内 1688 分销不能直接等价比较
- 其他国内平台存在各自订购页，但没有可确认的统一全套总价；真实组合优惠、续费、AI 额度、超量费和附加费用仍需下单取证

**可超越点：**

- 产品被拆成多个插件和软件，跨平台体验不统一
- 官网与产品表达偏传统，学习和选择成本高
- 可通过统一工作台、统一异常中心、透明状态和更现代的交互降低认知成本
- 当前可验证的抖店普通版年付仅折合 18 元 / 月，说明“更低价”是严格约束；Supplier 必须同时降低插件切换、异常处理和客服依赖带来的总使用成本

证据等级：**B，功能名称来自官方公开页面，真实行为待试用验证**。

### 3.3 爱用代发及爱用产品套件相关模块

[爱用代发官方页](https://www.aiyongtech.com/daifa/) 强调从 1688 货源到多平台履约的一体化路径。

**爱用代发页公开能力：**

- 1688 海量货源、批量多店铺货和自动商品优化
- 订单回流、一键下单、自动采购、物流自动同步和自动发货
- 铺货时自动调整并优化商品信息；具体调价、库存、换源和组合销售深度需要进入产品验证
- 支持淘宝、抖音、拼多多、1688、小红书、快手、视频号等多个平台
- 电脑、手机、旺旺三端共用功能权限

**爱用交易“新版分销代发”帮助页公开能力：**

- 邀请供应商建立合作关系，维护代发/退货地址，并把商品或 SKU 批量绑定到指定供应商
- 销售订单回流后可手工、批量或自动推单；自动模式支持延时审单以及按店铺/供应商转人工
- 订单可走 1688 一键/自动采购，也可按商品拆分给供应商密文打单；物流同步后自动发货，并支持取消未发货推送
- SKU 关联、多货源/组合销售、批量价格/库存更新、同款换源、未发货退款和退货地址等进阶能力来自爱用相关帮助页或特定产品模块，不能外推为所有代发助手版本均具备

这些供应商邀请、合作关系、SKU 绑定、延时审单和密文推单能力只能证明爱用产品套件中的特定模块，不能外推为所有“代发助手王”版本均具备。营销页多个平台的免费试用 CTA 还会进入同一 1688 登录/订购容器，平台标签与最终订购权益的对应关系需登录后核验。

**1688 接入形态：**

- “免费试用”进入 1688 优选工作台 ISV 应用容器，而不是普通独立 Web 页面
- 这证明其商业形态包含 1688 内嵌应用和服务订购；具体授权 scope 与原生/第三方能力边界仍未公开

**价格与试用表达：**

- 2026-07-30 更新的官方帮助价格表列出高级版最多 15 店：限时 35 元 / 月、常规 50 元 / 月、135 元 / 3 个月、240 元 / 半年、420 元 / 年
- 同一价格表列出企业版 16～200 店：899 元 / 月、2427 元 / 3 个月、4315 元 / 半年、7552 元 / 年
- 1688 官网 CTA 当前仍进入登录态订购链路，无法确认活动资格、最终成交价和续费价
- 页面同时出现“新客免费 3 个月”和 FAQ“免费 5 次铺货”等不同口径
- 2024 年基础手册另写免费版可绑定 5 店，可能已过期；免费 3 个月、5 次铺货和免费店铺额度能否叠加仍不明确
- 各套餐的订单量、铺货量、同步频率、超量费和模块权益关系仍未公开完整

**可超越点：**

- 首次访问难以快速理解 CTA 的最终去向和完整操作路径
- 代发助手、爱用铺货、爱用交易、新旧版分销和爱用 ERP 多入口并存；部分供应商协同要求对方额外注册
- 缺少明确的真实产品演示、迁移风险解释和套餐限制；官方文档还提示某些多店解绑会清空库存数据
- 可通过可交互演示、透明套餐、发布前预览和明确异常动作建立信任

证据等级：**B，营销页与特定模块帮助页已核对，模块间权益关系、付费与真实产品行为待账号验证**。

### 4.1 当前差距分层

**差异化价值仍缺验证：** 当前没有竞品真实试用的 A 级对照，也没有 5 名新用户对首次铺货、发布预检和异常修复的无指导测试；“更好用”仍是有代码基础的产品假设，而不是已被用户数据证明的结论。内测环境和验收状态以路线图为准。

**距离竞品基础能力追平仍缺：**

- 任意平台 SKU 编辑仍未实现；离线安全换源以及批量采集、上下架、改标题、改价、逐 SKU 库存同步与滞销安全下架已有应用侧切片，仍待真实平台验收
- 统一异常中心仍缺 staging、真实双租户和六域异常关闭证据；跨铺货/采购/批量操作的统一任务进度尚未收敛，销售售后到 1688 售后的工单关联也未形成闭环
- 除抖店外的第二、第三个销售平台完整 adapter，而不是只有入口或演示店
- 供应商邀请、合作关系、地址授权、SKU 绑定、延时审单和密文推单协同
- 1688 服务市场订购、试用、续费、退款、到期、卸载、权益同步和对账

**已经形成但尚待真实用户证明的优势假设：**

- 发布前一次展示利润、阻断、警告和处理入口，输入变化后旧结论自动失效
- 批量采集在详情读取前先去重预览，任务可刷新恢复、停止剩余和只重试失败项；成功结果进入独立“我的货源”，不把采集等同于收藏
- 重复请求、超时结果未知、迟到 worker、价格/库存变化和物流变化默认安全停止并可恢复
- 以一个响应式 Web 工作台承载核心路径，并用统一异常收件箱解释影响、责任和下一动作，减少多个插件、客户端、客服与页面之间的切换
- 内测费用、AI 用量和第三方费用边界先透明展示，再根据真实成本确定低于竞品的正式价格

## 5. Supplier 的差异化定位

> **一句话**：更简单、更安全，并以“价格更透明、可比口径目标更低”为原则的 1688 多平台分销经营工具。

### 基础价值

- 用一个工作台完成从货源到售后的完整经营闭环
- 用统一任务和异常中心替代多个插件、页面和人工表格
- 对错单、漏单、重复下单、重复发货和状态回退进行系统级保护

### AI 增强价值

- 选品不只看销量，还解释利润、竞争、履约、退货和供应稳定性
- 发布前统一预览标题、图片、类目、资质、价格、利润和风险
- 内容生成、类目映射和定价建议可编辑、可追溯、可降级
- 用真实经营结果持续校正推荐，而不是只输出通用文案

### 价格价值

- 同等店铺数、SKU、订单量和核心链路下，公开到手价目标低于主流竞品
- 当前 B 级价格锚点包括逸淘订单工具 216 元 / 年、已复核的逸淘商品工具 128 / 200 元 / 年，以及爱用高级版最多 15 店 420 元 / 年；此前记录的逸淘 888 元档仍待复核。逸淘订单工具与最低商品工具公开单买合计为 344 元 / 年，但不是已验证的组合成交价。Supplier 单平台核心版内部验证目标为 **不高于 199 元 / 年**：对 344 元拆分组合低约 42%，但对 216 元单一订单工具只低约 8%，只有店铺数、SKU、订单量和核心功能相同时才构成有效低价；在单位经济、首年/续费到手价和完整功能口径验证前，不作为已生效的对外永久价
- 基础经营功能不以 AI 点数为门槛
- 明示店铺数、铺货量、订单量、AI 配额、超额单价和所有附加费用
- 允许通过轻量套餐、可选 BYOK 和按量 AI 控制成本，不用隐藏收费补贴低价

### 易用性验收线

- 新商家不依赖人工培训，按“绑定账号 → 找货 → 利润 / 风险预览 → 铺货”完成首单；5 名新用户中至少 4 名独立完成
- 发布、采购、发货和售后都在同一个任务时间线显示当前步骤、预计等待、失败原因和下一动作，不让用户在多个插件间猜状态
- 100 SKU 批量任务必须先预览差异，再显示逐项进度和结果；失败项可单独重试，不重复执行成功项
- “更好用”至少用首次闭环完成率、完成耗时、异常自助恢复率和客服介入量证明；“更便宜”按同等用量的首年与续费总成本比较
- 套餐页在购买前展示店铺数、SKU、订单、铺货、AI 配额、超额费、试用、续费和退款规则；不能依赖客服解释完整价格

## 6. 优先级结论

### 必须先做

1. 形成可持续的邀请制内测环境，并用 5 名新用户验证首次铺货、发布预检和阻断修复
2. 用抖店 + 1688 完成真实小额订单闭环，验证发布、订单、采购、物流、退款和恢复
3. 补齐批量铺货、编辑、库存、上下架、换源和清理工作台
4. 在 staging 与真实异常上验收统一任务进度、失败重试和异常中心，并收口售后工单基础闭环
5. 完成服务市场订购、权益和对账，以及监控、恢复、合规、教程和客服

### 完成首发后再做

1. 按种子用户需求、市场价值和 OpenAPI 完整度选择下一平台（默认候选淘宝或拼多多）
2. 第一个新增平台闭环稳定后，再选择第二个平台
3. 快手、小红书、视频号继续按需求逐个接入
4. 供应商邀请、SKU 绑定、延时审单和按商品拆单协同
5. 自动售后和供应商替代
6. 浏览器插件与移动端关键待办

### 暂时不做

- 未完成资金风控前的免密自动支付
- Cookie 抓取或绕过平台规则的方案
- 与分销闭环无关的完整 ERP / 进销存
- 在抖店 + 1688 未真实验收前同时铺开多个平台

## 7. 核心用户与验证假设

首发目标用户不是按“白牌”或“AI 爱好者”定义，而是：

- 使用 1688 货源、希望在抖店低成本试销的单人或小团队商家
- 正在使用多个采集/铺货插件，希望减少操作和异常处理的人
- 对错单、漏单、库存失真和售后成本敏感，但没有专职技术团队的商家

必须用 10–30 家种子商家验证：

- 注册到首次成功铺货所需时间
- 真实发布、订单同步、采购和物流成功率
- 每 100 单需要人工处理的异常数和分钟数
- 退款、售后和供应异常造成的损失
- 用户对低价套餐、AI 配额和 BYOK 的接受度
- W1 留存、持续铺货率和付费意愿

## 8. 风险

| 风险                            | 影响 | 当前应对                                                     |
| ------------------------------- | ---- | ------------------------------------------------------------ |
| 平台 OpenAPI、资质或政策变化    | 高   | 只走官方 API；adapter 隔离；尽早申请测试权限和服务市场审核   |
| 真实平台行为与公开文档不一致    | 高   | 所有外部能力以真实账号 E2E 为完成标准                        |
| 自动采购或发货产生资金/错单风险 | 高   | 首发人工付款；幂等、租约、快照校验、审计和 fail-closed       |
| 同时扩多平台导致交付失控        | 高   | 一次只接一个平台，每个平台重复完整闭环 DoD                   |
| 低价导致 AI、客服和渠道成本失控 | 高   | 基础能力与 AI 成本拆分；配额透明；真实数据校准；保留 BYOK    |
| 竞品快速补齐 AI                 | 中   | 优势建立在完整体验、状态安全和真实经营数据，而非单个生成按钮 |
| 服务市场审核或上架延迟          | 高   | 资质与审核材料从 R0 并行准备，不等功能完成后再启动           |
