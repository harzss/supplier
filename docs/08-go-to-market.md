## 1. 商业目标

通过 1688 服务市场获得首批分销商家，用“完整经营闭环 + 更简单的体验 + 更安全的自动化 + 透明低价”替代需要多个插件拼接的方案。

首发不是追求大量注册，而是验证三件事：

1. 商家能否在较少人工指导下完成第一次真实铺货和履约。
2. Supplier 能否显著减少错单、漏单、重复操作和异常处理时间。
3. 低价套餐能否覆盖云资源、AI、平台分成、支付、客服和售后成本。

## 2. 定价原则

旧版 `¥39 / ¥99 / ¥299` 月费及 `¥399 / ¥999 / ¥2999` 年费是 2026-05 的历史假设，尚未经过真实竞品购买页和种子商家验证，停止作为对外报价。

当前受控邀请内测只展示软件订阅费 `¥0 / 内测期`：这不代表永久免费，不创建付费订阅，也不会自动扣费。模型 API、1688、销售平台及其他第三方服务产生的费用，由对应服务商另行收取。

新定价必须满足：

- **可比口径目标更低**：在店铺数、SKU、订单量和核心链路相当时争取低于主流竞品；具体差值只在真实价格取证和贡献毛利验证后确定。
- **当前内部价格护栏**：截至 2026-08-04，公开锚点包括逸淘订单工具 216 元 / 年、逸淘商品工具 128～888 元 / 年，以及爱用高级版最多 15 店 420 元 / 年；单个插件最低价不等于完整闭环的可比总价。Supplier 单平台核心版先按不高于 199 元 / 年测算和 A/B，未通过功能口径、真实成交价与贡献毛利门禁前不把该数字作为已生效的永久公开价。
- **全部费用透明**：展示店铺数、铺货量、订单量、AI 配额、超额单价、平台分成影响和附加服务价格。
- **基础闭环不被 AI 卡住**：采集、铺货、订单、人工采购、物流和售后基础能力不按 AI 次数收费。
- **AI 成本可控**：套餐含可理解的 AI 配额；内测超额先申请扩容或选择 BYOK，点数包只在计费验证后开放；降级时仍可使用基础经营功能。
- **不自动续费暗扣**：试用到期、续费和退款规则在购买前明确展示。
- **先验证再承诺**：价格只有在完成竞品价格取证、单位经济测算和种子用户测试后才标记生效日期。

| 套餐    | 目标用户             | 核心权益                                           | 价格状态                                              |

### 价格确定流程

1. 以真实账号分别复核逸淘订单与商品工具、爱用高级版及 1688 服务市场同类产品的到手价、续费价、店铺/订单/铺货限制和隐藏附加项，按“完整闭环总价”而非单插件最低价比较。
2. 用真实内测数据测算每店/月的 BFF、Supabase PostgreSQL（含队列与 `runtime_states`）、Auth、Storage、AI、监控、客服、退款和渠道成本。
3. 分别测试“低年费含基础 AI”和“更低基础费 + 按量 AI”，比较激活、使用和付费意愿。
4. 只有毛利、支持成本和留存均可持续时才确定正式价，并记录生效日期。

## 4. 上架前单位经济

每个套餐必须满足以下公式，不能只看 AI API 成本：

```text
单商家贡献毛利
= 实收订阅 + AI/附加服务收入
- 服务市场分成
- 支付与退款成本
- Supabase PostgreSQL / Auth / Storage / 计算 / 流量
- AI 与图片处理
- 监控、安全和备份
- 客服与异常处理人工
```

首发决策线：

- 基础套餐贡献毛利为正。
- AI 成本有硬上限，失败和重试不会重复计费。
- 每 100 个真实订单的人工异常处理时间可测量且持续下降。
- 年付折扣不会导致考虑退款和渠道分成后的负毛利。
- 若低价目标与成本冲突，优先收紧非核心 AI 配额，不隐藏收费或削弱订单安全。

## 5. 渠道顺序

### 5.1 邀请制内部测试

- 先在免费 SaaS 内测环境完成团队自测和真实小额订单验收。
- 通过已有商家关系邀请 3–5 家陪跑用户，逐单观察使用路径。
- 闭环稳定后扩到 10–30 家种子商家。

### 5.2 1688 服务市场

- 在功能开发期间并行准备开发者资质、应用审核、服务订购回调、隐私协议和客服材料。
- 上架前必须完成真实订购、续费、退款、到期、卸载、权益同步和对账。
- 首发小流量灰度并安排客服值守，不以未验证的销量或评分目标驱动冒险上线。

### 5.3 内容和社群

内容围绕真实问题而不是泛 AI 概念：

- 第一次从 1688 铺货到抖店需要几步
- 一笔订单如何采购、发货并处理异常
- 发布前如何判断利润、类目资质和供应风险
- Supplier 与多个插件组合的步骤、时间和总成本对比
- 真实案例中的失败、恢复和节省的人工时间

在没有真实案例前，不投放大规模广告，不承诺“全自动赚钱”或无法证明的收益。

| 阶段         | 准入条件                                             | 核心动作                                   | 退出标准                                     |

## 7. 核心指标

### 激活与易用性

- 注册 → 完成账号绑定率
- 账号绑定 → 首次成功铺货率
- 注册 → 首次成功铺货的中位时间
- 首次铺货中需要人工客服介入的用户比例

### 可靠性与经营价值

- 真实发布成功率和恢复成功率
- 订单同步完整率、采购成功率和物流回传成功率
- 每 100 单的阻断异常数、重复副作用数和人工处理分钟数
- 可计算利润的订单覆盖率、退款损失和供应异常率

### 留存与商业

- W1 / W4 活跃商家留存
- 每周持续铺货商家比例
- 试用 → 付费转化和退款率
- 每个套餐的实收 ARPU、贡献毛利和客服成本
- NPS、客服首次响应时间和问题解决时间

指标目标值在 3–5 家陪跑内测后建立基线，再用于 10–30 家种子内测；不沿用未经验证的历史目标。

## 8. 竞争应对

| 竞品动作           | Supplier 应对                                                  |
| ------------------ | -------------------------------------------------------------- |
| 头部工具增加 AI    | 强调可解释经营决策、完整闭环、异常恢复和真实效果，不比按钮数量 |
| 竞品短期大幅降价   | 保持总成本透明；用轻基础设施和分层 AI 降本，不做不可持续补贴   |
| 竞品覆盖更多平台   | 一次完成一个平台的全链路，不用 Logo 数量换取浅层支持           |
| 平台政策或接口变化 | adapter 隔离、功能开关、审计、回滚和及时用户提示               |
| 竞品强调“全自动”   | 明示自动化边界；对资金、错单和售后风险提供可暂停、可恢复的控制 |

## 9. 上架材料清单

- 产品名称、Logo、截图、真实操作视频和功能说明
- 套餐、限制、AI 配额、超额费用、试用、续费和退款规则
- 隐私政策、用户协议、数据处理清单和账号注销流程
- 服务订购、退款、到期、卸载回调和权益对账说明
- 新手教程、常见问题、故障公告入口和客服联系方式
- SLA、数据备份、故障恢复和安全事件响应说明
- 至少一个从 1688 货源到销售履约的真实案例

## 10. 历史假设处理

旧版“六周上架、三个月 5 万套、M3 MRR 5 万、基础版 ¥39/月、30% 固定平台分成”等内容缺少当前平台合同、真实成本和用户数据支持，全部降级为历史假设。后续如重新采用，必须写明数据来源、验证日期、适用套餐和负责人。
