# 09 · 主流程调通计划

> 目标：把产品的**核心业务闭环**端到端跑通，作为后续迭代的主干。
> 本文档只记录工程实施、测试和真实验收证据，不决定产品优先级或总体状态。产品方向、推进顺序与阶段状态以
> [00-roadmap.md](./00-roadmap.md) 为唯一来源；能否上线以
> [10-production-readiness.md](./10-production-readiness.md) 的 P0 门禁为准。
>
> 本文包含 M1～M86 的工程台账，状态文字应按证据日期理解；外部平台“应用侧已通”不等于真实 E2E 已验收。

## 1. 主流程定义（核心闭环）

```mermaid
flowchart LR
    A[采集 1688 货源] --> B[AI 打分选品]
    B --> C[浏览 / 商品详情]
    C --> D[AI 优化 标题/详情/主图]
    D --> E[一键铺货到店铺]
    E --> F[订单同步]
    F --> G[自动代发下单 1688]
    G --> H[回传物流]
    H --> I[售后与异常处置]
    I --> J[利润与经营复盘]
```

M60 已补齐运行时 schema readiness：数据库连通后继续验证仓库最新必需 migration 已完成且未回滚，漏跑 migration 的候选实例保持 liveness 但 readiness 返回 503。测试同时约束 readiness 常量必须跟随 migration 目录最新版本。

M61 已补齐抖店单笔订单详情的请求/响应关联：`order.orderDetail` 返回的父订单 ID 必须与请求 ID 完全一致，SDK 和 BFF 双层校验都在任何订单写入前 fail-closed；串单响应不会刷新错误订单，也不会把原订单的旧售后状态带入采购决策。

M62 已补齐订单同步与采购快照创建的并发隔离：两侧都使用可重试的 Serializable 事务；采购事务在锁定快照时重新读取当前售后、地址、SKU、货源映射和已有采购，并一次固化全部供应商采购项。同步和采购重叠时数据库会中止其中一个事务并重放，不会用同步前的旧 `offerId/specId/quantity` 创建真实 1688 订单。

M63 已补齐 OAuth Token 轮换后的本地持久化恢复：平台返回的新 access/refresh token 先以应用密钥加密写入 24 小时 Redis 恢复记录，再以旧密文条件最多重试 3 次写数据库；数据库瞬时失败时店铺保持 active，后续请求在同一刷新锁内恢复提交，不会误标过期或再次用已失效的旧 refresh token 调平台。只有平台明确拒绝刷新、凭证无法解密或店铺不匹配时才要求重新授权。

M64 已统一同一已发布商品的外部变更顺序：人工 `product.editV2`、平台状态回读和库存同步 worker 共用带 token/续租的 Redis 商品锁；库存 worker 在平台调用前二次确认任务所有权，人工修正在调用前确认货源库存版本未变化。并发修正不会乱序提交，本地状态回读不会覆盖修正结果，整 SKU 修正也不会把刚同步的新库存写回旧值。

M65 已补齐铺货长任务租约：worker 每 60 秒按 `running + attempts + lockedBy` 续写 `lockedAt`，使正常的长时 AI/图片/多店发布不会被 5 分钟 stale recovery 误接管。执行链在每个付费 AI、图片处理、Storage、店铺平台发布/恢复及结果写入前后校验所有权；旧 attempt 失权后立即停止后续外部调用，不再提交 complete/fail 或本地商品结果。

M66 已把铺货 AI 结果从“任务全部结束后一次保存”改为阶段性 checkpoint：标题、详情、详情图托管和主图处理每阶段都在下一个外部调用前写入 `ai_optimized`。详情和主图同时持久化 attempted 标记；合规拒绝、解析失败或 Storage 失败后若进程再被接管，新 attempt 会使用已保存结果或原图降级，不重复执行已计费阶段。

M67 已补齐已发货物流修复的长任务执行权：修复服务每 60 秒按 `repair id + running + lockedBy` 续租，不再依赖入口时一次性的 5 分钟锁。抖店 adapter 在承运商查询、订单回读、每个 `logisticsEditByPack` 和最终快照校验前后调用 ownership guard；旧请求失权后最多完成当前在途 HTTP，不会继续修改下一包或提交本地快照。

M68 已完成发布前利润与风险预检的应用侧闭环：只读 API 聚合独立阻断和警告，生产身份下严格按租户、有效 seller 与非演示店过滤；定价权限失败不会返回受限报价，资质只读取已有缓存，未知依赖错误对客户端脱敏并在服务端保留诊断。Web 只接受与当前输入指纹和当前价格凭证一致的结果，任何输入变化都会清除旧结论；正式提交继续全量复核。
