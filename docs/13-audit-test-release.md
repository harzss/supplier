> 目标：从 2026-08-18 到 2026-08-31，用 10 个工作日形成可提交 1688 服务市场审核的邀请制测试版本。D10 的承诺是“满足 Gate 后提交审核”，不是承诺平台在 D10 前审核通过。
>
> 当前运行边界：`5cd6b28` 已完成 Supabase staging 45→46 备份恢复演练与真实迁移，post-audit 为 46/46、pending 0、schema diff matched、46/46 public 表 RLS；Shadowrocket 独立直连 Module 已启用，固定 Gateway 与本机 BFF 均返回该 revision，18/18 smoke 通过。审核模式 Cloudflare 静态 Web 已发布为 version `488ee083-f2e8-4e08-8bbc-9b77baebb264`。真实 Auth、抖店、1688、Railway、商业回调和合规仍未验收，详见 [本轮证据](./evidence/2026-08-18-marketplace-entitlement-staging.md)。

## 1. 发布名称与边界

本轮正式名称统一为：**Supplier 抖店 + 1688 邀请制审核测试版**。

本轮不宣称：

- 已公开商用、已正式上架或已通过平台审核；
- 已支持多销售平台、多店、全自动采购或自动售后；
- 已验证批量经营、完整 SKU 编辑、AI 主图或正式付费套餐；
- 已证明 10～30 家商家的留存、毛利或 SLA。

## 2. D10 最小范围

### 2.1 必须交付

- 邀请制 Supabase 邮箱账号；两个真实账号完成设密、登录、刷新、退出、找回密码、旧密码失效和核心数据隔离。
- 单个抖店销售店 + 至少两个受控 1688 买家账号的真实 OAuth 与权限证据。
- 1688 搜索、详情、SKU、价格、库存和一件代发条件的真实回读；跨买家数据口径完成核对。
- 单商品利润试算、人工内容确认、抖店发布、审核状态回读、修正和下架。
- 真实销售订单回流，按稳定 `outOrderId` 创建/恢复 1688 采购，付款继续人工确认。
- 已承诺物流范围内的真实包裹回传和抖店平台回读；未验收的包裹场景必须显式阻断。
- 取消、退款、Token 失效、结果未知和迟到结果进入可审计的人工处置，不得重复发布、采购或发货。
- 服务市场订购、试用、续费、退款、到期、卸载事件的验签、幂等、乱序处理、权益同步、对账和异常记录。
- 独立生产 Supabase、常驻 BFF 计算、稳定域名、Secret、监控告警、备份恢复、前向修复与切流/回滚证据。
- 隐私政策、用户协议、数据处理清单、注销流程、客服入口、教程、FAQ、测试账号、截图、操作视频和至少一条真实闭环案例。

### 2.2 本轮后移

- 批量采集、批量上下架/标题/价格/库存、完整 SKU 编辑和 100 SKU 成功率门禁；
- 自动异常扫描、自动采购、免密付款、自动退款、自动退货和自动替代货源；
- AI 主图/GPU 处理、AI 点数包、自动续费和正式价格；
- 多店、多销售平台、供应商协同、浏览器插件和移动端；
- 10～30 家规模验证；审核通过后先陪跑 3～5 家，再决定扩量。

后移能力必须在页面、审核文案和套餐说明中隐藏或标明未开放，不能只把后台开关关掉却继续对外承诺。

## 6. 风险接受边界

可以接受并在审核材料中公开：

- 邀请制、单店、低流量、人工付款、人工售后；
- 免费测试期、正式价格未确定；
- 未开放功能隐藏并保持开关关闭；
- 审核后只陪跑 3～5 家，安排每日订单核对和客服值守。

不可接受：

- 用 staging 冒充独立生产环境；
- 跳过 Auth、租户隔离、签名、幂等、平台回读、备份恢复或监控告警；
- 开启未验收的采购、库存、批量、SKU 或异常扫描 worker；
- 在平台未明确接受的情况下把资质写成“办理中即可”；
- 用提交审核替代“审核通过”，或用审核通过替代真实订购与邀请制灰度验收。

## 7. D10 之后

平台阶段单独计算：受理 → 补件/整改 → 审核通过 → 邀请制小流量灰度 → 至少一笔生产订购/权益/退款闭环 → 无 P0 后扩大开放。平台审核没有仓库内可承诺的 SLA。
