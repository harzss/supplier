## 1. Supplier 当前能做什么

本次候选聚焦一条受控路径：

> 受邀账号登录 → 绑定一个抖店销售店和受控 1688 买家账号 → 查找一个真实货源 → 查看利润/风险 → 人工确认内容 → 发布并回读 → 销售订单回流 → 创建或恢复 1688 采购 → 人工付款 → 回读已验收包裹并回传抖店 → 处理异常/售后。

这是邀请制审核测试版，不是公开商用版本。批量经营、完整 SKU 编辑、自动采购、免密付款、自动退款、自动售后、自动替代货源、AI 主图、正式价格、多店和其他销售平台暂不开放。

## 2. 审核员/邀请用户上手步骤

以下步骤是待验收脚本，不代表当前环境已经全部可执行。

1. 从指定邮箱接收邀请，通过官方链接设置专用密码。
2. 使用提审方提供的 HTTPS 地址登录；不要把密码或验证码发给客服。
3. 在设置页确认账号和环境状态，再按引导绑定抖店和 1688。
4. 选择经运营批准的测试货源，核对 offer、SKU、价格、库存和一件代发条件。
5. 进行单商品利润试算；缺少成本或规则时不得把估算当作确定利润。
6. 人工确认标题、图片、类目、资质、SKU 和价格后发布测试商品。
7. 等待抖店平台回读审核/上下架状态；如驳回，按原因修正后重提。
8. 使用批准的小额测试订单，让销售订单回流；核对商品、数量、金额和收件快照。
9. 创建或恢复同一个 1688 采购单，**由授权付款人手工付款**。
10. 供应商发货后核对运单、承运商、商品项和数量，再回传抖店并从平台回读。
11. 在异常/售后页面处理结果未知、Token 失效、取消或退款；不要反复点击产生重复副作用。

审核专用账号、货源、店铺、订单预算和安全步骤见 [审核测试账号说明](./reviewer-test-account.md)。

## 3. 常见问题

### 为什么不能自行注册？

当前是邀请制审核测试版，公开注册保持关闭。账号必须由提审/运营负责人通过受控流程邀请。

### 为什么需要授权抖店和 1688？

Supplier 仅通过官方 API 读取用户有权管理的店铺、商品、订单、采购和物流状态，并执行用户确认的操作。用户应使用专用测试店铺/账号，按最小权限授权。

### Supplier 会自动付款吗？

不会。首期仅创建或恢复 1688 采购单，付款由用户或其授权付款人手工确认。不要向 Supplier 提供支付密码或免密凭证。

### 为什么某个操作被阻断？

当 Token 失效、类目/资质缺失、SKU/价格/库存/地址快照变化、平台结果未知、退款竞态或包裹映射不完整时，系统应停止而不是猜测。请记录页面上的脱敏 request ID 和下一步提示，通过已验证客服入口处理。

### 超时后可以再次点击发布、采购或发货吗？

不要立即重试。超时不代表平台没有成功。先从 Supplier 和对应平台回读同一业务键/订单的最终状态；无法确认时进入人工处置。

### 可以批量采集、批量铺货或完整编辑 SKU 吗？

不属于本次提审承诺。相关页面应隐藏，后台开关保持关闭。

### AI 是必需的吗？

不是。AI 是可选辅助，失败时应保留人工编辑路径。所有 AI 结果都要人工核对，尤其是类目、资质、价格、库存、知识产权和平台规则。

### Supplier 会保存哪些信息？

候选可能处理账号、店铺授权、商品、订单、加密收件信息、采购、物流、售后、权益、AI 用量和安全审计。最终范围、第三方、留存和用户权利以法务批准并生效的隐私政策为准；当前底稿见 [隐私政策](./privacy-policy.md)。

### 如何解绑店铺或注销账号？

解绑店铺和注销 Supplier 账号是不同操作。当前端到端注销能力尚未验收；发布前必须通过 [账号注销流程](./account-deletion.md) 的 P0 Gate。不要发布不存在的按钮或联系方式。

### 如何联系客服或报告安全问题？

**P0 TODO：真实客服、隐私和安全入口尚未提供。** 发布时只能展示经过值守和演练的渠道。客服不会索要密码、验证码、Token、Cookie、模型密钥或完整收货信息。

### 当前有正式 SLA 或赔偿吗？

没有已批准的正式 SLA。邀请制响应目标、覆盖时段和故障沟通方式仍待真实值守演练和法务批准，见 [客服与 SLA](./support-and-sla.md)。

### 价格、试用和退款规则是什么？

尚未确定。历史价格假设不构成报价。任何收费前必须在页面和服务市场明确展示店铺/SKU/订单/AI 配额、超额费用、试用、续费、退款、到期和卸载规则。

## 4. 安全自查

- 只使用提审方确认的 HTTPS 地址和官方平台授权页。
- 不共享账号，不复用个人/生产店铺的高权限密码。
- 不在客服、截图或视频中暴露密码、验证码、Token、Cookie、密钥、完整手机号和地址。
- 每次发布、采购、发货和退款前核对影响对象；结果未知时停止。
- 审核结束后由提审负责人轮换密码、撤销会话和平台授权。

## 5. 已知限制

- 真实 Auth 双账号、抖店/1688、服务市场回调、真实订单/物流/退款、注销、客服和合规材料仍需按 D9 Gate 验收。
- 未验收功能必须同时从页面、文案、套餐和后台开关中移除/关闭。
- 平台审核没有仓库内可承诺的完成时间；D10 目标是满足 Gate 后提交，不是保证审核通过。
