## 2. 账号安全要求

1. 使用专用审核邮箱和独立强密码，不复用任何生产/个人账号密码。
2. 由受控管理员邀请；保留脱敏邀请事件，不把邮箱和密码写入 Git、CI 日志或聊天记录。
3. 完成设密、登录、JWT 刷新、退出、找回密码、旧密码失效和无 Token 访问 401 验收。
4. 使用第二个专用账号证明店铺、收藏、铺货、订单、密钥和工单等核心域互不可见。
5. 审核期间账号不得被自动化脚本、浏览器和多人并发共用，避免会话失效或测试相互污染。
6. 审核结束后撤销全部会话和平台授权，轮换/销毁密码并按批准规则清理测试数据。

## 4. 建议审核路径

### A. 账号与隔离

1. 接收邀请并设置密码。
2. 登录工作台，刷新页面后会话仍有效。
3. 退出后旧 refresh token 不可复用；完成一次找回密码后旧密码失效。
4. 使用账号 B 验证无法看到账号 A 的店铺、收藏、铺货、订单、BYOK 密钥和工单。

### B. 平台授权与货源

1. 在设置页绑定批准的抖店测试店和 1688 买家账号。
2. 查看授权、到期和联调准备度；Token 失效时能明确重新授权。
3. 搜索批准货源，核对 offer、详情、SKU、价格、库存和一件代发条件。
4. 用两个 1688 买家账号核对已声明的数据口径。

### C. 单商品发布

1. 查看利润和风险；缺少成本/规则时应阻断虚假精确利润。
2. 人工确认标题、图片、类目、资质、SKU 和价格。
3. 发布到抖店，记录唯一平台商品 ID，并从平台回读审核状态。
4. 完成一次修正重提和下架；不能生成重复商品。

### D. 订单、采购和物流

1. 创建受控小额销售订单并同步回流。
2. 核对销售订单和收件快照后创建/恢复同一个 1688 采购单。
3. 授权付款人手工付款；Supplier 不接收支付密码或免密凭证。
4. 供应商发货后核对运单、承运商、商品项和数量，再回传抖店并平台回读。

### E. 异常与权益

1. 演示 Token 失效、结果未知或退款/取消进入可审计人工处置；不得重复发布、采购或发货。
2. 用服务市场测试账号验证签名拒绝、重复幂等、乱序收敛、退款/到期/卸载停权和对账。

## 6. 每轮审核前检查

- [ ] 候选 SHA、域名、数据库 migration 和 readiness 一致。
- [ ] 审核账号可登录，密码和找回邮件可达；无并发使用。
- [ ] 两账号核心域隔离已重跑。
- [ ] 抖店/1688 授权和测试资源仍有效。
- [ ] 所有未验收功能在 UI、文案、套餐和开关中均关闭。
- [ ] 测试订单预算、付款人、收货人和供应商时间窗仍有效。
- [ ] 客服/故障入口真实可达，值守人知晓审核窗口。
- [ ] 清理计划和停止条件已确认。

## 7. 停止条件

发现跨租户、错单、重复单、错误收件、资金不一致、平台结果未知、签名/权益异常、Secret 泄露或未验收功能可执行时立即停止审核动作，关闭对应副作用并转人工复核。不得为了演示完成而绕过 Gate。

## 8. 审核后清理

1. 回读并下架/删除测试商品（按平台允许范围）。
2. 核对销售、采购、付款、退款、物流和权益最终状态。
3. 撤销审核账号会话、抖店/1688 OAuth 和临时权限。
4. 轮换/销毁密码；删除仓库外临时凭证。
5. 按批准规则清理账号与测试数据，并保留脱敏证据索引。
